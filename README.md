# Trading Bot — Data Ingestion + Signal Generation

Real-time market data pipeline for Indian equities (NSE) that ingests price
ticks, news, and fundamentals into TimescaleDB via a Redis message queue,
then runs a signal engine over that data to detect sentiment, volume
anomalies, and price patterns.

## Architecture

```
Price stream  (Angel One WebSocket)     ─┐
News poller   (Google News RSS  /30s)    ├──► Redis Streams ──► Consumer ──► TimescaleDB
Fundamentals  (Screener.in scrape /day) ─┘                                ──► Redis hash (latest prices)

Signal Engine (FinBERT sentiment, volume anomaly, breakout/support)
    reads recent ticks/news from Redis ──► Redis Stream (signals) ──► Consumer ──► TimescaleDB
```

## Prerequisites

- Python 3.11+
- Redis running locally (`redis-server`)
- PostgreSQL with TimescaleDB extension
- An Angel One SmartAPI account (API key, client code, PIN, TOTP secret) —
  needed for the real-time price stream. News (Google News RSS) and
  fundamentals (Screener.in) are scraped directly and need no API key.

## Setup

```bash
# 1. Clone and enter the project
cd tradingbot

# 2. Create a virtual environment
python -m venv .venv
source .venv/bin/activate        # Mac/Linux
.venv\Scripts\activate           # Windows

# 3. Install dependencies
pip install -r requirements.txt

# 4. Copy and fill in your API keys
cp .env.example .env
# Edit .env with your actual keys

# 5. Create the database
psql -U postgres -c "CREATE DATABASE tradingbot;"
psql -U postgres -d tradingbot -c "CREATE EXTENSION IF NOT EXISTS timescaledb;"

# 6. Create the logs directory
mkdir logs
```

## Running

```bash
python main.py
```

The bot will:
1. Check all connections (Redis, TimescaleDB, API keys)
2. Run database migrations (creates tables if they don't exist)
3. Start all ingestion tasks concurrently, plus the signal engine
4. Log all activity to stdout and `logs/tradingbot.log`

Stop with `Ctrl+C` — it shuts down cleanly.

## Querying your data

Once the bot is running, you can inspect data in TimescaleDB:

```sql
-- Latest 20 ticks for RELIANCE
SELECT time, price, volume FROM ticks
WHERE symbol = 'RELIANCE'
ORDER BY time DESC LIMIT 20;

-- Average price per minute (TimescaleDB time_bucket)
SELECT time_bucket('1 minute', time) AS bucket, avg(price)
FROM ticks WHERE symbol = 'RELIANCE'
GROUP BY bucket ORDER BY bucket DESC;

-- Recent news mentioning RELIANCE
SELECT published_at, title, source_name
FROM news_articles
WHERE 'RELIANCE' = ANY(symbols)
ORDER BY published_at DESC LIMIT 10;

-- Recent signals generated by the signal engine
SELECT time, symbol, signal_type, value, confidence_score
FROM signals
ORDER BY time DESC LIMIT 20;
```

## Evaluating signal quality

Before building a decision layer on top of the signal engine's output,
check whether its signals actually predict favorable forward price moves:

```bash
python -m evaluation.signal_evaluation
```

For every signal in the `signals` table, this looks up the price at signal
time and the price 5/15/60 minutes later, and prints a per-`(signal_type,
value)` summary — sample count, mean/median forward return, and (for
directional signals like sentiment and breakout/support) a win rate.
Volume anomalies have no predicted direction, so those are reported by
return magnitude only. You'll need the bot to have been running for a
while first so there's enough signal + tick history to evaluate.

## Next steps (Phase 3)

Once signal evaluation shows which signals actually have edge, Phase 3
will:
- Combine the validated signals into an actual buy/sell decision
- Apply risk management (position sizing, stop-loss)
- Place and track orders through Angel One's trading API
- Backtest the combined strategy's P&L against historical tick data before running live
